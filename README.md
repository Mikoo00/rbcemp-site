# Сайт «РБ №2-ЦЭМП» для Open Server Panel 6 (PHP 8.5)

Сервер на PHP, база данных SQLite (один файл, MySQL и phpMyAdmin не нужны).
Подходит и Apache, и Nginx. Нужен PHP 8.1 или новее (рассчитано на 8.5) с расширениями `pdo_sqlite` и `mbstring`.

## Установка

1. Меню Open Server (правой кнопкой по значку в трее) → **«Корневой каталог»** → откроется папка панели, в ней папка **`home`**.
2. Распакуйте архив **в `home`** так, чтобы получилась папка **`home\rbcemp.local`**, а внутри неё лежали `.osp`, `public`, `app`, `data`, `config.php`. (Не должно быть лишней вложенной папки вида `home\rbcemp-php\rbcemp.local`.)
3. В меню нажмите **«Перезапустить»**. В списке сверху, рядом с `phpmyadmin`, появится **`rbcemp.local`**. Именно файл `.osp\project.ini` делает папку проектом: без него панель домен не показывает.
4. Нажмите на `rbcemp.local` в меню и выберите для проекта **PHP 8.5** (и веб-сервер: Apache или Nginx, на ваш выбор). Если пунктов выбора нет, откройте `.osp\project.ini` и добавьте строку `php_engine = PHP-8.5`. Точное название возьмите из списка «Модули» в меню. После этого снова «Перезапустить».
5. Проверка: откройте `http://rbcemp.local/api.php?r=/health`. Должно быть что-то вроде  
   `{"ok":true,"php":"8.5","pdo_sqlite":true,"mbstring":true}`  
   Если `pdo_sqlite` равно `false`, включите расширение `pdo_sqlite` в настройках PHP (в конфигурации PHP строка `extension=pdo_sqlite` без `;` в начале) и перезапустите.
6. Создайте администратора: `http://rbcemp.local/setup.php` (ФИО, email, пароль от 8 символов). Страница работает только с вашего компьютера и только пока нет администратора.
7. Откройте `http://rbcemp.local/` и войдите. Панель управления — отдельная страница **`http://rbcemp.local/admin.html`**: на неё же ведёт аватар → «Панель администратора» (для модератора — «Панель модератора»). Если не выполнен вход, страница сама покажет форму входа сотрудников.

Хотите другое имя домена? Переименуйте папку и **такое же** имя в квадратных скобках в `.osp\project.ini`.

База создаётся сама при первом обращении (папка `data`). **Для резервной копии копируйте папку `data`.**

## Структура

```
rbcemp.local\
  .osp\project.ini    настройки проекта для Open Server (веб-корень = public)
  public\             единственная папка, доступная из браузера
    index.html        сайт
    admin.html        панель администратора / модератора (отдельная страница)
    api.php           API (вход, роли, записи, отзывы, резюме, реклама)
    setup.php         создание первого администратора
  app\bootstrap.php   база данных, проверки, сессии  (из браузера недоступно)
  data\               база SQLite                    (из браузера недоступно)
  config.php          настройки                      (из браузера недоступно)
  cli.php             консольные команды
```

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| Домен `rbcemp.local` не появился в меню | Проверьте, что папка лежит прямо в `home`, называется так же, как имя в `[...]` в `.osp\project.ini`, и в ней есть папка `.osp` (она начинается с точки). Нажмите «Перезапустить». Посмотрите «Просмотр журналов» |
| Открывается «Index of /» или переход на `/public/` | Панель не применила `public_dir`. Сайт при этом работает по адресу `http://rbcemp.local/public/`. Чтобы исправить, проверьте строку `public_dir = {base_dir}\public` в `.osp\project.ini` |
| Страница не открывается / ошибка 502 | Включите нужные модули (PHP и выбранный веб-сервер) в меню «Модули» |
| Ошибка 500 | Откройте «Просмотр журналов» и пришлите последнюю ошибку |
| «Не включено расширение pdo_sqlite» | Включите `pdo_sqlite` в настройках PHP (п. 5) |
| На сайте «Сервер вернул неожиданный ответ» | PHP не обрабатывает `api.php`: выберите PHP в настройках проекта и перезапустите |
| «Запрещённый источник запроса» (403) | Открывайте сайт всегда по одному адресу (не смешивайте `localhost` и `rbcemp.local`) |
| Не удаётся записать в базу | Папка `data` должна быть доступна для записи |
| Забыли пароль администратора | Меню → «Интерфейс командной строки», затем `cd /d путь\к\home\rbcemp.local` и `php cli.php set-password email@example.ru НовыйПароль123` |
| Сделать админом уже зарегистрированного | `php cli.php make-admin email@example.ru` (в той же консоли и папке) |

## Роли

| Возможность | Пользователь | Модератор | Администратор |
|---|:--:|:--:|:--:|
| Запись на приём, свой кабинет, отмена своей записи, смена пароля | ✔ | ✔ | ✔ |
| Оставить отзыв | на модерацию | публикуется сразу | публикуется сразу |
| Обрабатывать записи, модерировать отзывы | — | ✔ | ✔ |
| Просматривать резюме | — | — | ✔ |
| **Выдавать роли**, блокировать, удалять пользователей, сбрасывать пароли | — | — | ✔ |
| Настройки рекламы, журнал действий | — | — | ✔ |

Роль выдаётся в панели управления (`admin.html`) → «Пользователи» → список «Роль». Действует сразу. Нельзя снять роль, заблокировать или удалить самого себя, а также убрать последнего администратора.

## Реклама

На странице два рекламных блока (перед «Новости» и «Вакансии»). Настройка: `admin.html` → «Реклама».

- **Свои баннеры** (по умолчанию включены, есть два примера). Показываются всегда, без согласия на cookie. Ссылка может вести на внешний сайт или на раздел сайта: `#appointment` (запись на приём), `#contacts` и т. п.
- **Google AdSense** или **Реклама Яндекса (РСЯ)**: укажите ID блоков из своего кабинета. Работают только на домене, одобренном сетью, и только у посетителей, разрешивших маркетинговые cookie.
- Блок с рекламой сети остаётся скрытым, пока сеть не показала объявление. Если за несколько секунд она ничего не показала (localhost, домен не одобрен, нет объявлений), вместо неё показывается ваш баннер. Если баннеров нет, блок не показывается вовсе: ни рамки, ни надписи «Реклама».
- На `localhost` рекламные сети **ничего не покажут** (это ограничение самих сетей), поэтому проверять на нём можно только свои баннеры.
- Рекламные сети собирают данные посетителей: добавьте это в Политику конфиденциальности. Для сайта больницы в кабинете сети отключите категории рекламы лекарств, БАДов и платных медуслуг.

## Безопасность

- Из браузера доступна только папка `public`. База, настройки и код ядра лежат выше неё, поэтому защита не зависит от того, Apache у вас или Nginx. Имя файла базы случайное.
- Пароли хранятся как хеш (`password_hash`), сессия в защищённой httpOnly-cookie (в БД лежит только хеш токена), 7 дней.
- Права проверяются **на сервере**. Защита от CSRF (только JSON + проверка Origin), ограничение частоты попыток входа и форм, экранирование данных на странице, запросы к БД только параметризованные.
- Настройки в `config.php`: ключ для `setup.php` на сервере, прокси, часовой пояс, срок сессии.

## Выкладка в интернет (кратко)

Нужен хостинг с PHP 8.1+ и `pdo_sqlite`. Сделайте так, чтобы веб-корнем была папка `public`, а `app`, `data`, `config.php` лежали выше неё. Задайте `setup_key` в `config.php` (длинная случайная строка) и откройте `setup.php?key=ВАШ_КЛЮЧ`. Включите HTTPS (cookie станет Secure автоматически). Если сайт за прокси или Cloudflare, поставьте `trust_proxy` в `true`.

## Панель управления (admin.html)

Отдельная страница, не индексируется поисковиками (`noindex`). Разделы: обзор, записи, отзывы, пользователи, резюме, реклама, журнал (последние четыре видит только администратор; модератору доступны обзор, записи и отзывы). Адрес вкладки сохраняется в ссылке (`admin.html#users`), в таблицах есть поиск и фильтр по статусу, в меню показаны счётчики новых записей, отзывов и резюме. Все права по-прежнему проверяются на сервере в `api.php`: страница лишь скрывает недоступные разделы.
